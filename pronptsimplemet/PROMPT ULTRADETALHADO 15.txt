# MÓDULO 15 — GERENCIAMENTO INTELIGENTE DE ARQUIVOS, DOCUMENTOS E WORKSPACES

## 1. OBJETIVO PRINCIPAL

Implemente um sistema completo de gerenciamento de arquivos e documentos dentro do harness de IA.

O sistema deverá permitir que os agentes trabalhem com arquivos reais do computador e dos projetos, incluindo leitura, criação, edição, comparação, busca, organização e geração de documentos.

Não implemente apenas uma interface visual de explorador de arquivos. Desenvolva uma camada funcional que possa ser utilizada pelo Agent Core, pelos subagentes, pelo planejador, pelas ferramentas MCP e pelos demais módulos.

O objetivo é que o harness consiga executar solicitações como:

- Encontrar um arquivo específico em um projeto.
- Ler e resumir documentos extensos.
- Localizar informações dentro de vários arquivos.
- Criar e editar documentos.
- Comparar duas versões de um arquivo.
- Organizar arquivos de um workspace.
- Extrair informações de PDFs e planilhas.
- Gerar relatórios com base em arquivos existentes.
- Identificar arquivos relacionados a uma tarefa de programação.
- Criar estruturas de diretórios para novos projetos.
- Trabalhar com vários arquivos sem perder o contexto.
- Produzir resultados verificáveis e registrar as alterações realizadas.

Antes de implementar, inspecione a arquitetura atual do harness, o sistema de arquivos já existente e os módulos de contexto, terminal, inteligência de código, Git, plugins e MCP.

Não presuma que o projeto utiliza uma linguagem ou framework específico. Adapte todas as implementações à stack existente.

## 3. ARQUITETURA DO MÓDULO

Implemente os componentes equivalentes abaixo, reutilizando os serviços existentes quando disponíveis.

### 3.1. File System Service

Crie uma camada central para operações de arquivos e diretórios.

Deve suportar:

- Listar arquivos e pastas.
- Consultar metadados.
- Ler arquivos.
- Criar arquivos.
- Editar arquivos.
- Renomear arquivos.
- Copiar arquivos.
- Mover arquivos.
- Criar diretórios.
- Consultar tamanhos e datas de modificação.
- Detectar alterações.
- Comparar versões.
- Identificar tipos de arquivo.
- Obter informações de codificação.
- Identificar arquivos binários.
- Consultar permissões quando disponíveis.

Implemente operações assíncronas quando apropriado e evite bloquear a interface enquanto arquivos grandes são processados.

Não carregue automaticamente arquivos enormes inteiros na memória. Utilize leitura em intervalos, streaming ou processamento por partes quando necessário.

### 3.2. Workspace Manager

Implemente gerenciamento de workspaces e projetos.

Cada workspace deve possuir:

- Identificador.
- Caminho raiz.
- Nome.
- Tipo de projeto, quando identificado.
- Data da última utilização.
- Arquivos indexados.
- Configurações próprias.
- Histórico de operações.
- Estado da indexação.

Permita abrir, criar, alternar e fechar workspaces.

A seleção do workspace deve ser compartilhada com o Agent Core, o terminal, o Git, a inteligência de código e o sistema de contexto.

Quando o usuário alternar de projeto, os agentes devem receber o contexto do workspace correto, sem misturar indiscriminadamente arquivos ou informações de projetos diferentes.

### 3.3. File Search Engine

Implemente busca por arquivos e conteúdo.

Permita pesquisar por:

- Nome.
- Extensão.
- Caminho.
- Texto contido no arquivo.
- Expressões regulares.
- Metadados.
- Data de modificação.
- Tipo de arquivo.
- Símbolos e definições, por meio do módulo de inteligência de código.

Inclua filtros para excluir diretórios de dependências, arquivos gerados, caches e pastas configuradas pelo usuário.

A busca deve funcionar com projetos grandes e apresentar resultados progressivamente quando necessário.

Para código, reutilize o mecanismo de busca e indexação existente, evitando criar uma segunda implementação concorrente.

### 3.4. Document Reader

Implemente um sistema extensível para leitura e extração de conteúdo de diferentes formatos.

Comece pelos formatos mais úteis:

- TXT.
- Markdown.
- JSON.
- XML.
- YAML.
- CSV.
- HTML.
- PDF.
- DOCX.
- XLSX.
- Logs.
- Código-fonte.

Quando a ferramenta adequada estiver instalada e integrada, permita adicionar suporte a outros formatos.

O sistema deve separar a extração do conteúdo da interpretação realizada pela IA.

Sempre que possível, preserve:

- Nome do arquivo.
- Caminho.
- Número de página.
- Número da linha.
- Nome da planilha.
- Intervalo de células.
- Títulos e seções.
- Metadados relevantes.

Essas informações deverão permitir que o agente apresente a origem das informações utilizadas em uma resposta.

### 3.5. Document Writer

Implemente criação e edição de documentos.

Permita que os agentes:

- Criem arquivos Markdown.
- Produzam documentos estruturados.
- Gerem relatórios.
- Criem arquivos CSV.
- Criem ou editem documentos DOCX.
- Gerem ou modifiquem planilhas XLSX.
- Produzam arquivos JSON, YAML e XML válidos.
- Convertam documentos entre formatos compatíveis.
- Criem estruturas de pastas para entregas.

Utilize bibliotecas apropriadas para cada formato.

Não simule a criação de um documento apenas retornando seu conteúdo na conversa. O sistema deve salvar o arquivo no destino solicitado e verificar o resultado.

Após criar um arquivo, valide sua existência e, quando aplicável, sua integridade estrutural.

### 3.6. Document Conversion Service

Crie um serviço extensível para conversões entre formatos.

Considere:

- Markdown para HTML.
- Markdown para PDF, quando houver mecanismo adequado.
- DOCX para PDF, quando houver LibreOffice ou outro conversor compatível.
- CSV para XLSX.
- Extração de texto de PDF.
- Conversão de documentos para formatos intermediários de análise.

Antes da conversão, verifique se a ferramenta necessária está instalada.

Não declare uma conversão concluída quando a ferramenta estiver ausente ou o comando falhar.

Preserve o arquivo de origem por padrão. A substituição de um arquivo existente deve ser uma operação explícita.

## 4. SISTEMA DE EDIÇÃO E PATCHES

### 4.1. File Editing Engine

Implemente edição confiável de arquivos.

Deve suportar:

- Substituição de conteúdo.
- Inserção e remoção de trechos.
- Edição por linhas.
- Edição por intervalo.
- Aplicação de patches.
- Edição estrutural quando houver parser compatível.
- Verificação do conteúdo após a gravação.
- Detecção de conflitos com alterações externas.

Antes de modificar um arquivo, registre informações suficientes para identificar a versão utilizada na edição.

Se o arquivo tiver mudado entre a leitura e a gravação, detecte o conflito e evite sobrescrever silenciosamente a alteração mais recente.

Para alterações de código, reutilize o mecanismo de edição estrutural e o sistema de Git já implementados.

### 4.2. Diff Viewer

Implemente comparação visual entre:

- Arquivo original e arquivo modificado.
- Duas versões de um documento.
- Conteúdo atual e conteúdo proposto.
- Alterações produzidas por diferentes agentes.
- Versões recuperadas do Git.

Quando possível, apresente diferenças por linha e destaque inserções, remoções e modificações.

Para arquivos binários, apresente metadados e indique que não é possível realizar uma comparação textual convencional.

### 4.3. Histórico e recuperação

Registre operações importantes de escrita, edição, renomeação e movimentação.

Permita consultar:

- Arquivo afetado.
- Operação executada.
- Horário.
- Agente responsável.
- Tarefa relacionada.
- Versão anterior disponível.
- Resultado da operação.

Integre o histórico ao Git e ao mecanismo de recuperação existente, em vez de criar cópias redundantes de todos os arquivos.

Quando não houver Git, utilize um mecanismo de histórico apropriado para os arquivos que precisam de recuperação.

Não sobrescreva silenciosamente versões anteriores.

Para leitura de arquivos extensos, ofereça operações de intervalo ou paginação.

Para operações em lote, registre quais itens foram processados e quais falharam.

## 6. INTEGRAÇÃO COM A IA

Integre o módulo ao Agent Core e ao sistema de contexto.

O agente deve poder localizar arquivos relevantes, ler apenas os trechos necessários e consultar o conteúdo conforme a tarefa.

Para documentos extensos:

1. Identifique o formato.
2. Extraia o conteúdo.
3. Divida-o em unidades adequadas.
4. Preserve a origem de cada trecho.
5. Recupere os trechos relevantes para a solicitação.
6. Envie o contexto necessário ao modelo.
7. Produza uma resposta fundamentada no conteúdo recuperado.

Reutilize o indexador e a memória de projeto já existentes.

Não envie indiscriminadamente todos os arquivos de um workspace ao modelo.

Quando uma resposta depender de um documento, preserve referências ao arquivo e às páginas, linhas ou seções que sustentam a resposta, quando disponíveis.

## 7. INDEXAÇÃO E ATUALIZAÇÃO

Implemente um indexador incremental.

Ele deverá:

- Detectar arquivos novos.
- Detectar alterações.
- Detectar arquivos removidos.
- Atualizar apenas os registros afetados quando possível.
- Permitir reconstruir o índice.
- Apresentar o estado da indexação.
- Registrar erros de leitura.
- Respeitar as exclusões configuradas.
- Integrar-se ao sistema de contexto e à inteligência de código.

Utilize mecanismos de observação de arquivos compatíveis com a plataforma atual.

Na ausência de suporte confiável a eventos de alteração, implemente uma estratégia de verificação alternativa.

Evite reindexar todo o projeto a cada pergunta.

## 8. INTERFACE GRÁFICA

Se o harness possuir interface gráfica, implemente uma área de arquivos com:

- Navegação por diretórios.
- Pesquisa.
- Filtros.
- Visualização de metadados.
- Pré-visualização de documentos.
- Editor de texto.
- Comparação de versões.
- Histórico de alterações.
- Estado da indexação.
- Acesso aos workspaces.
- Abertura de arquivos relacionados à tarefa atual.

A interface deverá utilizar os serviços reais do backend.

Não crie botões decorativos que não executem operações.

A abertura e a edição de arquivos devem preservar o estado atual do usuário sempre que possível.

Para formatos sem pré-visualização nativa, apresente uma mensagem clara e permita abrir o arquivo com um aplicativo externo, quando a plataforma oferecer esse recurso.

- Indexação incremental.

- Cancelamento de buscas.
- Limites configuráveis de resultados.
- Processamento assíncrono.
- Paginação.
- Evitação de leituras duplicadas.
- Limpeza de caches obsoletos.

Meça o desempenho em projetos de teste de tamanhos diferentes.
